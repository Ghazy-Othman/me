Ksa-Store

The project is a fully integrated e-commerce store tailored for the Saudi market. When I say “integrated,” I mean a production-ready MVP prepared for deployment. I built the project in stages using Laravel, and at each stage I delivered a store with new features and tested them manually.

Web & API
I built the web pages using Livewire, and I also developed the API to support a potential mobile application. However, I noticed that a significant amount of code was being duplicated between the API controllers and the Livewire components. To solve this, I restructured the project and adopted the Service Pattern to separate shared business logic from logic specific to controllers or components. I chose this approach because it made the project cleaner, more maintainable, and more scalable.

Authentication & Authorization
For authentication on the web side, I relied on Laravel's default session-based system. For the API, I used Sanctum (token-based authentication). In addition, I implemented social login using Laravel Socialite to allow users to sign in via Google, Facebook, X, and other providers. But what if a user wants to complete a purchase without creating an account? That is where Guest Mode comes in. Through Guest Mode, users can complete the entire purchase and payment process while providing the required shipping information during checkout. However, if there is a shipping process, how can a guest track the order status? I addressed this by building a dedicated order-tracking page where any user (guest or registered) can enter the order ID and check the current status.

Admin
To build the admin dashboard, I used Filament (and honestly, it's excellent). From the control panel, the admin can view products, categories, orders, and users, with full create and delete capabilities. The admin also has access to a dedicated analytics page that provides system and order insights. The entire dashboard is real-time and event-driven.

E-Payment & Webhooks
The payment gateway used is Moyasar, which supports cards, MasterCard, Mada, and Apple Pay. I encountered an important challenge: how can the order status be updated if the user closes the browser before the callback executes, or if the connection drops for any external reason? The answer is webhooks. I implemented webhook handling to ensure the order status is updated regardless of the user's actions or network conditions.

Caching
This is where performance optimization becomes interesting. To improve system performance and user experience, caching was the first strategy I implemented. I cached data that was frequently requested but rarely changed. The real challenge, however, was determining when to invalidate the cache and I handled that carefully. For example, I cached active categories displayed on the store page. To invalidate this cache correctly, I created an observer on the Category model that clears the cache whenever a category is added or removed. Another example is caching product details based on the product slug (I avoid exposing numeric IDs and instead use slugs or UUIDs). In this case, it would not be efficient to clear the cache whenever a new product is added or removed. Instead, I invalidate the cache only when the specific product is updated. You might ask: why cache individual products at all, especially if there are around one million products? The answer is that a product is cached only after a user visits its page. This means that only the most frequently visited products are cached -- potentially less than 10% of the total inventory.

Advanced Cart Logic
Using simple sessions for the cart was not sufficient, as sessions eventually expire. Instead, I implemented a hybrid system: a database-driven cart linked to a long-lived cookie (or a header ID for the mobile API). This ensures the cart persists even if a guest returns days later. Additionally, if a guest decides to log in, I implemented logic to automatically merge their guest cart items into their main account cart. I also separated quantity logic to prevent subtle bugs: Adding an item increments the quantity (+=). Updating an item from the cart page sets the exact value (=). Small implementation details like these help prevent major logic issues.

Localization & Security
To provide a tailored experience, I built a custom middleware engine to handle localization (Arabic/English) intelligently. The system checks the API header first (for mobile apps), then the user's database preference, followed by cookies, and finally the system configuration. From a security perspective, I avoided shortcuts. I implemented rate limiting on the checkout and login endpoints to prevent brute-force and card-testing attacks. I also protected the API against IDOR vulnerabilities by ensuring that users (and guests) can modify only the cart items they actually own, enforced through strict service-level checks.

Real-Time & Architecture
To ensure a responsive user interface, I used the Event-Listener pattern combined with queues. Heavy operations such as sending OTP codes, welcome emails, or order status notifications are never processed synchronously; instead, they are dispatched to background workers. To make the dashboard and user profile feel dynamic, I utilized Laravel Reverb for real-time broadcasting. When an order status changes, an event is triggered and the frontend updates instantly without requiring a page refresh.

Testing
One of the hardest lessons I learned in my career is that the time and effort required to write tests during development are far less than the effort needed to fix defects later. The project became significantly more complex because features were initially shipped without proper testing. I admit that I neglected testing at the beginning, especially unit testing. When I eventually started writing tests, I was surprised by the number of bugs that surfaced. Those issues could have significantly reduced system reliability if the application had been in production. Since then, I have adopted a more disciplined approach. I write both unit and feature tests to validate the system before introducing new functionality, using PHPUnit. Now, whenever I add a new feature, I do not feel comfortable until I run the full test suite successfully.
